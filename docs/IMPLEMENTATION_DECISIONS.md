# 0.2.0 实现取舍与验证边界

本轮按用户要求交付本地测试版，由用户在 Illustrator 中测试；没有代为安装、重启、关闭文档或运行实机验收。

## 实施中确定的取舍

1. 源码中禁用原生文字接口只是静态约束，另保留递归检查所有文档对象的验收代码。真实文档对象审计仍待本地执行；若有遗漏，单靠源码检查不能发现所有异常对象。
2. 非法 Unicode 在写入表格数据时立即拒绝，不等到保存时才拒绝。代价是错误输入会直接失败，避免损坏数据进入排版。
3. 文字簇边界同时参考 Windows 排版和系统字素分段，避免删除半个组合字符。代价是要求 Windows 10 1903 或更新系统。
4. 实际缩放、DPI 和滚动换算在画布预览及宿主接入层处理，排版模块测试物理字号。真实 AI 的视图换算仍待本地测试，不能用反向数学换算当作实机证据。
5. 表格数据保持自身尺寸，从矢量边框读取整表的横向、纵向缩放。代价是命中和显示必须同时使用两个方向的比例；审查发现的边缘容差问题已进入回归修复，旋转和倾斜仍不保证编辑。
6. 文字编辑预览通过 AI 辅助显示绘制临时像素，避免独立浮窗遮挡侧栏。代价是预览本身为像素；保存的表格字形和导出仍为矢量路径，不保存预览图片。
7. 会话身份和连续输入批次规则独立测试，验证不会接受另一文档的输入，以及修改成功后才更新光标。代价是这类测试不能证明 AI 真实撤销事务行为，仍需用户测试。
8. “不用文本框”约束适用于正文、隐藏输入代理以及底层 AI 文字对象。行列数、尺寸、字号等数字参数继续使用普通对话框控件；若数字参数也要禁用控件，需要另行重做参数界面，正文架构不受影响。

## 最终审查

独立审查覆盖本次整个实现，未发现 Critical 问题；发现并处理组合字符接合后的光标与组字范围，以及内部字形锁定、隐藏保护两项 Important 问题。缩放后边缘命中容差虽然被初评为 Minor，也按影响格内操作的 Important 问题一并修复。每项添加回归后重新检查，不把代码审查当作实机验收。

## 明确保留给本地测试的项目

- 搜狗和微软拼音的真实消息顺序、候选位置、确认与取消。
- 侧栏停靠、实际 DPI / 缩放 / 滚动裁切、撤销分组、保存重开、PDF 外观及真实对象审计。
- AI 的回滚是否完整恢复被删除对象的句柄和关联。模拟 SDK 只证明回滚请求会执行，不能证明真实宿主结果。
- 数字参数控件按上述第 8 项保留，不承担正文输入。
- 旋转、倾斜、旋转视图、竖排和彩色字形、旧文字框表格自动迁移不在本次保证范围；可能需要重新建表或更换排版方式。

本轮没有搁置其他 Minor 修饰项。PDF 表格文字为轮廓，无法按普通 PDF 文字搜索或选择。
